Diferencial 1 — Os Desafios

Proatividade e uma faca de dois gumes


Fadiga de notificacao e o risco #1. Se as notificacoes parecem irrelevantes ou frequentes demais, o usuario desativa e nunca mais volta. Calibrar isso exige dados reais de usuarios reais.

Limiares de saude nao sao universais. FC de 55bpm e normal para corredor, alarmante para sedentario. HRV de 30ms pode ser estresse ou baseline. O MVP usa multiplicadores fixos — precisa evoluir para personalizacao individual.

Apple controla a plataforma. iOS decide quando e com que frequencia o monitoramento em background roda. Se o usuario forca o fechamento do app, os gatilhos param. Construimos sobre uma plataforma que nao controlamos.

Diferencial 2 — Os Desafios

O maior desafio tecnico do produto


O modelo ML de deteccao nao existe ainda. Pesquisas publicadas atingem 85% precisao / 81% recall em condicoes controladas. No mundo real sera menor. Treinar requer dados de usuarios reais comendo de formas diferentes.

Falsos positivos frequentes. Escovar dentes, beber agua, cocar o rosto — todos envolvem movimento mao-boca. Se o watch pergunta "Comendo agora?" enquanto voce escova os dentes, a confianca erode.

Bateria do watch e restricao real. Monitoramento continuo de acelerometro + giroscopio num dispositivo com bateria do tamanho de uma moeda. Se VitalAI drena bateria visivelmente, usuario desinstala.

Confirmacao intencional. Escolhemos sempre pedir confirmacao com 1 toque. Nunca sera "friccao zero" — mas mantem o usuario consciente do que come e garante qualidade dos dados.

Diferencial 3

Loop de Feedback Nutricional


Perfil → Contexto detectado → Sugestao personalizada → Feedback → Aprendizado → Sugestao melhor


Cada avaliacao torna a proxima sugestao mais alinhada ao gosto real do usuario.

Isso cria um custo de troca — sair significa comecar do zero.

Diferencial 3 — Os Desafios

De "simples" a "inteligente" e um salto grande


O aprendizado atual e primitivo. Hoje, o sistema apenas exclui receitas com nota ≤ 2 estrelas. Nao entende ingredientes, sabores, padroes contextuais. Personalizacao real exige modelo de recomendacao com ML.

Problema de cold start. Usuarios novos tem zero historico. As primeiras 2-3 semanas de sugestoes sao essencialmente aleatorias. Se forem ruins, o usuario desiste antes do sistema aprender.

Fadiga de feedback. Pedir avaliacao apos cada refeicao adiciona friccao. Usuarios avaliam as primeiras com entusiasmo, depois param. Precisamos equilibrar coleta de dados com experiencia.

Regulatorio e Privacidade


Posicionamento: Wellness, nao diagnostico. "Seu HRV esta baixo, tente respiracao" = wellness. "Seu padrao cardiaco sugere risco de arritmia" = ANVISA. A linha fica mais tenue conforme adicionamos features.


LGPD. Dados de saude sao "dados sensiveis". Consentimento explicito, direito a exclusao, portabilidade. Arquitetura desenhada para isso. Implementacao parcial — precisa completar antes do lancamento.


Privacidade por design. Processamento on-device — dados biometricos brutos nunca saem do aparelho. Apenas eventos classificados sao enviados ao backend.
